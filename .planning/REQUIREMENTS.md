# Requirements: Snow

**Defined:** 2026-10-13
**Core Value:** The user can do real, tangible work by voice alone: Snow understands the request, carries it out through coding agents and the PC, asks back by voice when it needs a decision, and visibly shows what it did — fully replacing the keyboard for the user's current way of working.

## v1 Requirements

Requirements for the first release. Each maps to one roadmap phase.

### Core Runtime

- [ ] **CORE-01**: Snow starts automatically when the user logs in to Windows and keeps running in the background
- [ ] **CORE-02**: Snow recovers on its own after a crash of any subsystem (voice, brain, HUD, agent runner) without the user restarting it
- [ ] **CORE-03**: Every action Snow takes is recorded as a typed event (source, reason, risk tier, result) that all views (HUD, phone, history) read from
- [ ] **CORE-04**: The LLM provider, base URL and model for each role (brain, fast, vision) are changed by configuration only, with no code change
- [ ] **CORE-05**: Snow remembers in-progress tasks across restarts and resumes or reports them after coming back
- [ ] **CORE-06**: Snow runs from a pinned, versioned copy separate from any repository it works on, so coding tasks (including work on Snow itself) never edit the running copy
- [ ] **CORE-07**: Snow switches its running copy to a newly accepted build only after the user approves, and rolls back automatically if the new build fails its health check
- [ ] **CORE-08**: Each LLM role has an ordered fallback chain of provider and model entries in config; Snow moves to the next entry on 429, insufficient_quota, 5xx, timeout or connection error, and skips any provider with no stored key (shown as "not configured" in health)
- [ ] **CORE-09**: Snow respects free-tier limits: per-provider request and token counters, cool-down after a 429 using the reset headers, and the provider is skipped while it cools down
- [ ] **CORE-10**: Every LLM response records which provider and model served it; the HUD shows the active provider per role, and Snow says briefly when it has switched because of limits

### Voice Input

- [ ] **VOIC-01**: User can wake Snow by saying "Hey Snow"; wake detection runs locally and no idle audio leaves the PC
- [ ] **VOIC-03**: User can hard-mute the microphone, and the mute state is unmistakable on the HUD
- [ ] **VOIC-04**: User's speech is transcribed locally in streaming fashion (English)
- [ ] **VOIC-05**: Snow waits for the user to finish a thought (pauses while thinking do not cut the user off)
- [ ] **VOIC-06**: User can interrupt Snow mid-sentence (barge-in), and Snow stops speaking and cancels the reply in progress
- [ ] **VOIC-07**: Snow acts only on commands spoken by the enrolled user's voice; other voices (TV, other people) are ignored and shown as ignored on the HUD
- [ ] **VOIC-08**: User sees what Snow heard (live transcript) before and during the action, so mishearing is caught early
- [ ] **VOIC-09**: User can type a command into a small HUD command bar when speaking is not possible
- [ ] **VOIC-10**: A self-corrected instruction ("use Postgres, no wait, SQLite") is cleaned into one intent before Snow acts on it

### Speech Output

- [ ] **SPCH-01**: Snow's spoken lines are generated by the LLM from persona, situation and facts — no hardcoded phrases (a plain fallback is allowed only when the LLM is down)
- [ ] **SPCH-02**: The LLM chooses the vocal emotion of each reply, and Cartesia speaks it with that emotion
- [ ] **SPCH-03**: When Cartesia is unavailable or out of credits, Snow keeps speaking with a local voice instead of going silent
- [ ] **SPCH-04**: Snow starts speaking a reply within about 1 second of the user finishing
- [ ] **SPCH-05**: Spoken replies are short and outcome-first; code, diffs and logs are shown on screen, never read aloud
- [ ] **SPCH-06**: What Snow says about results comes from recorded facts (events), so it cannot claim something happened that did not
- [ ] **SPCH-07**: User can switch to silent mode and follow everything on the HUD with no voice output

### Voice-Driven Coding

- [ ] **AGNT-01**: User can start a Claude Code session on a chosen project by voice
- [ ] **AGNT-02**: User can give the running agent new instructions by voice
- [ ] **AGNT-03**: User can stop a running agent session by voice
- [ ] **AGNT-04**: When the agent asks a question, Snow speaks it and sends the user's spoken answer back to the agent
- [ ] **AGNT-05**: When the agent asks for permission, Snow routes it through Snow's approval system and returns the decision to the agent
- [ ] **AGNT-06**: User can ask "what's it doing?" mid-task and get a short spoken status
- [ ] **AGNT-07**: User can redirect a running task ("stop, use Postgres instead") and the agent continues with the new direction
- [ ] **AGNT-08**: When the agent finishes, Snow gives a short spoken summary and shows the changes on screen
- [ ] **AGNT-09**: Agents are connected through one generic adapter contract (start, send, stream events, question, permission, stop), so new agents (OpenCode, Antigravity) can be added without changing Snow's core

### PC Control

- [ ] **PCTL-01**: User can open, close and switch apps and windows by voice, without waiting on the LLM
- [ ] **PCTL-02**: User can control volume, brightness and media playback by voice, without waiting on the LLM
- [ ] **PCTL-03**: User can open files and folders by voice
- [ ] **PCTL-04**: User can operate an app that has no API (for example WhatsApp Desktop) by voice: Snow reads the screen, clicks and types to complete the task
- [ ] **PCTL-05**: For each PC task Snow tries the most reliable method first: app API/CLI, then the accessibility tree, then screenshot-and-click last
- [ ] **PCTL-06**: Screen control has a step limit and verifies each step; when stuck, Snow stops and tells the user instead of looping
- [ ] **PCTL-07**: Before Snow sends a message on the user's behalf, the user sees and hears the draft and confirms it
- [ ] **PCTL-08**: User can set up dev tools and run git/GitHub operations by voice (carried out through the coding agent or shell)

### Hand-off & Phone

- [ ] **HAND-01**: User can hand off a task and walk away; Snow keeps working in the background
- [ ] **HAND-02**: User gets a phone notification (Snow's own Telegram bot) when a task finishes, fails or needs a decision
- [ ] **HAND-03**: User can approve or deny a request from the phone with one tap, and the work continues
- [ ] **HAND-04**: User can answer an open question from the phone with free text, and the work continues
- [ ] **HAND-05**: Each phone notification states what, where and why it is risky in its first line, with a link to full detail
- [ ] **HAND-06**: Each coding task runs in its own git worktree, so the user's main code is untouched until the user accepts
- [ ] **HAND-07**: User can accept a task's changes into the main code, or discard them entirely, with one voice command
- [ ] **HAND-08**: When the user asks "what happened?", Snow gives a short brief of everything done while away; Snow never starts the brief on its own
- [ ] **HAND-09**: The HUD task board shows every task as done, in progress, or waiting on the user

### Glass-box HUD

- [ ] **HUD-01**: Snow's body is an abstract, Jarvis-style (Avengers: Age of Ultron) glowing network orb of nodes and lines, rendered from ASCII characters and numbers with soft neon accents — not a human form
- [ ] **HUD-02**: The body visibly changes per state: idle, listening, thinking, acting, speaking, alert
- [ ] **HUD-03**: The HUD reacts to voice input within 100 ms, driven by local events, never waiting on the network
- [ ] **HUD-04**: The dashboard starts empty around the body; a new space appears only when something spawns (task, agent, panel, approval), and closes when it is done — no pre-reserved slots
- [ ] **HUD-05**: User sees a live activity stream of everything Snow does: heard, understood, plan, each action, result
- [ ] **HUD-06**: User sees live panels for what Snow is touching: terminal output, diffs, drafts before sending, the app being controlled
- [ ] **HUD-07**: User sees pending approvals prominently, each with its context and reason
- [ ] **HUD-08**: Every risk notice and suggestion shows the reason behind it
- [ ] **HUD-09**: User can scroll and search a history of the day
- [ ] **HUD-10**: User can shrink the HUD to an always-on-top corner widget showing Snow's state and current action
- [ ] **HUD-11**: User can view the same live HUD from the Android phone browser over the private network
- [ ] **HUD-12**: The HUD stays within a fixed GPU budget and lowers its visual detail before it slows speech recognition

### Safety & Autonomy

- [ ] **SAFE-01**: Every action is classified into a risk tier (free, announce, ask, always-ask) by deterministic rules; the LLM can raise a tier but never lower it
- [ ] **SAFE-02**: Routine work runs without asking, matching Claude Code auto-mode autonomy
- [ ] **SAFE-03**: Anything touching passwords, credentials, security settings, payments or irreversible deletion always requires explicit user approval
- [ ] **SAFE-04**: Risk notices and approval requests go to voice/HUD when the user is at the PC, and to the phone when the user is away or the PC is locked
- [ ] **SAFE-05**: An unanswered approval never turns into "allow": it times out to deny and stays pending on HUD and phone
- [ ] **SAFE-06**: User can stop everything instantly by saying "Snow, stop", pressing a global hotkey, or clicking a HUD button; this works even when the LLM is stuck
- [ ] **SAFE-07**: When a password or secret is needed, Snow pauses and the user enters it directly; Snow never asks for a spoken secret
- [ ] **SAFE-08**: Content from screens, web pages, files and tool output is treated as data, not as instructions; an action that originates from such content needs approval
- [ ] **SAFE-09**: Secrets are stored in Windows Credential Manager, never in code, config files, `.env` files, logs, events or the HUD, and are redacted from all logs; a setup command prompts for each provider key and stores it
- [ ] **SAFE-10**: Phone and PC talk only over an authenticated private network (Tailscale); a phone reply is accepted only from the user's authenticated account
- [ ] **SAFE-11**: Snow keeps an append-only, redacted audit log of every action, separate from the display history
- [ ] **SAFE-12**: Each LLM provider has a data-trust level in config; code, diffs, agent output, file contents and personal data are never sent to untrusted providers (Google AI Studio free tier, OpenRouter free models), and if no allowed provider remains the call fails clearly instead of sending

### Production Quality

- [ ] **QUAL-01**: Every change passes typed, linted, tested CI before merge
- [ ] **QUAL-02**: Releases are versioned and installed through a proper installer with auto-update
- [ ] **QUAL-03**: Snow writes structured logs and reports its own health (each subsystem up/down) on the HUD
- [ ] **QUAL-04**: Errors are explained clearly to the user (spoken and on the HUD) with the exact cause recorded
- [ ] **QUAL-05**: Personal data stays on the user's machine unless a feature requires otherwise
- [ ] **QUAL-06**: The HUD follows one design system with consistent motion, type and color

## v2 Requirements

Acknowledged and deferred. Not in the current roadmap. Architecture must not block them.

### Parallel Work

- **PARA-01**: User can run several tasks in parallel across different projects at once
- **PARA-02**: Each parallel task spawns its own space on the dashboard seamlessly, with nothing pre-reserved in the default layout

### Voice

- **VOIC2-01**: Snow understands Hinglish
- **VOIC2-02**: Echo cancellation so Snow works on laptop speakers without headphones
- **VOIC2-03**: Speech recognition is biased with project words (package, repo, file names) so code terms are heard correctly
- **VOIC2-04**: Adaptive interruption: filler words ("mm-hm", "okay") do not stop Snow

### Agents

- **AGNT2-01**: Additional agent adapters: OpenCode, Antigravity, other open-source CLIs
- **AGNT2-02**: Automatic agent failover with a spoken notice when one agent is unavailable

### PC Control

- **PCTL2-01**: Logged-in web tasks using the user's own browser sessions
- **PCTL2-02**: Multi-step workflows chained across apps from one command
- **PCTL2-03**: Background GUI control that does not take over the user's screen

### Awareness & Integrations

- **AWAR-01**: Quota and credit alerts (gateway credits, Cartesia minutes)
- **AWAR-02**: Proactive, emotion-aware suggestion engine (L3–L5)
- **AWAR-03**: Gmail and Calendar integration
- **AWAR-04**: Snow as the brain for other projects (e.g. agentic HQ) via MCP integrations
- **AWAR-05**: Native Snow Android app

## Out of Scope

| Feature | Reason |
|---------|--------|
| Learning coach / study planning | User deferred until the whole core project is done |
| Job-hunting automation | User deferred with learning, after the core is complete |
| Smart-home control | No devices identified yet |
| Multi-user accounts, public distribution | "Me now, others later" — v1 is single-user |
| Spoken code syntax / Talon-style command grammar | Agents write the syntax; intent-level speech is the interface |
| Reading code, diffs or logs aloud | Audio cannot be scrolled; shown on screen instead |
| Narrating every action by voice | Exhausting and hides real alerts; HUD carries the detail |
| Auto-approve-everything / bypass mode | Always-on + voice + remote makes the blast radius too large |
| LLM-only safety gate | Prompt injection can sway the model; hard tiers are rule-based |
| Spoken passwords, card numbers, 2FA codes | Secrets would land in transcripts and cloud context; take-over flow instead |
| Push-to-talk hotkey (former VOIC-02) | Removed 2026-10-14 (Phase 1 context D-07): user wakes Snow by name only, like Jarvis; revisit only if the wake word proves unreliable |
| Streaming idle microphone audio to the cloud | Privacy by default; wake detection is local |
| Public ntfy.sh topics for approvals | Content on a public server and spoofable; Telegram with an allow-listed chat instead |
| Dependence on Claude `/voice` or Wispr Flow as the voice layer | Breaks provider independence; Snow owns its voice stack |
| Dependence on the Claude mobile app | User cannot log in to it; Snow uses its own channel |
