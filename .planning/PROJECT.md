# Snow

## What This Is

Snow is an always-on, Jarvis-style personal AI that runs on the user's Windows laptop and reaches them on their Android phone. The user speaks ("Hey Snow…") instead of typing, and Snow does the work: it drives coding agents (Claude Code, Antigravity, OpenCode and others), operates the PC and any app on it, and shows everything it is doing on a living ASCII-rendered HUD. It is built for one user now, engineered so others could install it later, and held to the polish bar of a product shipped by a top-tier company.

## Core Value

The user can do real, tangible work by voice alone: Snow understands the request, carries it out through coding agents and the PC, asks back by voice when it needs a decision, and visibly shows what it did — fully replacing the keyboard for the user's current way of working.

### Active

**Voice core**
- [ ] Always-on background service that starts with Windows and recovers from crashes
- [ ] Wake phrase "Hey Snow" detected locally (no cloud audio while idle)
- [ ] Natural two-way conversation: streaming speech-to-text, streaming replies, user can interrupt mid-sentence (barge-in)
- [ ] Human-sounding voice: every line generated by the LLM from persona + situation + memory — no hardcoded scripts; the LLM also picks the vocal emotion per reply, in response to the user's tone
- [ ] Only the user's voice can command Snow (speaker verification); TV/other voices are ignored

**Voice-driven coding (replace the keyboard)**
- [ ] User can start, steer and stop coding-agent sessions entirely by voice
- [ ] Pluggable agent adapters — Claude Code, Antigravity, OpenCode and other CLIs — switchable by voice or automatically when one is unavailable
- [ ] When an agent asks a question or a permission, Snow speaks it and relays the user's spoken answer back
- [ ] Snow reports outcomes in a short spoken summary; code and diffs are shown on screen, never read aloud
- [ ] User can ask for status mid-task and redirect the work ("stop, use Postgres instead")

**Advanced PC control**
- [ ] Open/close/switch apps, windows, volume, brightness, media, files and folders by voice
- [ ] Any-app control via screen understanding (see the screen, click, type) for apps with no API
- [ ] Multi-step workflows chained across apps from one command
- [ ] Developer environment setup: install tools, configure projects, fix environment issues, git/GitHub operations
- [ ] Logged-in web tasks: fill forms, operate sites with the user's existing sessions

**Hand-off work + notifications**
- [ ] User can hand off a long task, walk away, and Snow keeps working in the background with saved state
- [ ] Snow notifies the user on their Android phone when a task finishes, fails, or needs a decision — via Snow's own channel, with no dependency on the Claude app or any specific account
- [ ] User can answer Snow's questions from the phone and the work continues
- [ ] On return, the HUD shows a task board: done, in progress, waiting on the user

**Glass-box HUD**
- [ ] Living ASCII-shader 3D HUD (3D scene rendered as glyphs, color kept, glow) with distinct states: idle, listening, thinking, acting, speaking, alert
- [ ] Activity stream of everything Snow does: heard → understood → plan → each action → result
- [ ] Live panels for what Snow is touching: app being controlled, diffs, terminal output, drafts before sending, pages being read
- [ ] Every proactive suggestion shows its reason
- [ ] Pending approvals and a scrollable history of the day
- [ ] Silent mode: follow everything visually with no voice
- [ ] HUD reacts within 100 ms of voice input; layout adapts to full screen, corner widget, and phone

**Safety & autonomy**
- [ ] Autonomy matches Claude Code auto mode: Snow acts freely on routine work
- [ ] Risky actions are announced; how depends on presence — voice/HUD when the user is at the PC, phone notification when away
- [ ] Anything touching passwords, credentials, security settings, payments or irreversible deletion always requires explicit user approval
- [ ] Remote access between phone and PC only over an authenticated private network (e.g. Tailscale)
- [ ] Secrets live in a secure local store, never in code or logs

**Production quality**
- [ ] Clean, typed, linted, tested codebase with CI on every change and versioned releases
- [ ] One design system for the HUD; polished motion; clear errors; fast startup
- [ ] Proper installer, auto-update, structured logs and health monitoring
- [ ] Privacy by default: personal data stays on the user's machine unless a feature requires otherwise

### Out of Scope

- Learning coach / study planning — user explicitly deferred until the whole core project is done
- Job-hunting automation (job search, cover letters, application tracking) — deferred with learning, after the core is complete
- Full proactive/emotion-aware suggestion engine (L3–L5: rule-based → reasoning → learning) — built after voice-driven work is solid; v1 lays the senses/memory foundation only where voice-driven work needs it
- Smart-home control — no devices identified yet
- Native Snow Android app — v1 uses a ready-made push channel (ntfy/Telegram); dedicated app is a later milestone
- Multi-user accounts and public distribution — "me now, others later": architecture must not block it, but v1 ships single-user

## Context

- **Who:** a single developer (the user) who currently codes by typing into Claude Code, Antigravity and open-source-model CLIs, and wants to stop typing entirely. Snow should feel like "another person" who does the work when spoken to.
- **Inspiration:** Jarvis from Iron Man — situational awareness, natural conversation, control across all devices — explicitly *not* like existing voice coding tools.
- **Visual direction:** an "ASCII MMORPG" reference video — a real 3D scene passed through an ASCII shader, glyph color preserved, glowing light sources, letters revealed on zoom. Idea: Snow's body is built from glyphs of the user's own code. Reference families: film UI (Jayse Hansen, Territory Studio), game UI (gameuidatabase.com).
- **Agent landscape:** the user rotates between Claude Code (borrowed account), Antigravity and open-source models because paid access is not guaranteed — Snow must never depend on one provider.
- **Hardware:** Windows 11 laptop — Intel i5-12500H (12 cores), 16 GB RAM, NVIDIA RTX 4050 Laptop (6 GB VRAM); Node 25, Python 3.10, Git installed. Android phone.
- **Model access:** free tiers only, across five OpenAI-compatible providers: Experiential Labs (credits shared with the user's other projects), Groq, Google AI Studio, NVIDIA NIM and OpenRouter free models. Each Snow role (brain, fast, vision) has an ordered fallback chain in config (see Phase 1 context D-20 to D-30). These LLMs are only Snow's own brain; coding work runs on the user's Claude Code and Antigravity subscriptions.
- **Draft scenarios (intent, not scripts):** morning brief; voice coding with questions back; agent permission requests; WhatsApp send with read-back; incoming message at a natural pause; meeting reminder; frustration detected; late-night care; job hunt; phone remote check on a build; focus mode; learning from dismissals; PC/media control without confirmation; ignoring commands from voices that are not the user's.
- **Proactivity model (for later milestones):** senses → world model → memory → judgment/interrupt policy (urgency × relevance × interruptibility) → feedback; emotion read from voice tone, words and behavior.

## Constraints

- **Budget:** free for now — runs on free provider tiers and gateway credits; the user plans to pay for an API later — so the LLM layer must be swappable by configuration, not code
- **Provider independence:** no hard dependency on Claude, the Claude app, or any single account/provider — agent and model access come and go
- **Hardware:** 6 GB VRAM — the laptop should do as little heavy work as possible; local models limited to small CPU ones (wake word, live speech-to-text, tone detection, everyday voice, speaker verification); large LLMs stay remote
- **Platform:** Windows 11 primary host; Android for mobile
- **Voice (revised 2026-10-15):** Pocket TTS on CPU is the everyday voice; Cartesia (free credits) speaks only big emotional moments; Chatterbox on GPU only when on mains power and the GPU is idle; kokoro-onnx last fallback. Snow detects the user's tone locally and answers in kind
- **Speech-to-text (revised 2026-10-15):** Groq cloud Whisper for final transcripts (user approved Groq hearing conversation turns); local Moonshine on CPU for live words and offline fallback. Wake detection stays local; no idle audio leaves the PC
- **Wake word:** local (openWakeWord, trainable on "Hey Snow")
- **Latency:** HUD feedback < 100 ms; spoken reply starts in roughly 1 second or Snow stops feeling human
- **Security:** voice + always-on + remote access + full permissions is a high-risk combination — speaker verification, approval tiers, authenticated tunnel and secret isolation are mandatory, not optional
- **Quality bar:** production-grade, "built by a multi-billion-dollar company" polish — clean, maintained, documented, tested
