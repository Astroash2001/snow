## Phase Goal

**As a** developer, **I want to** wake Snow by voice and talk with it naturally, **so that** I can speak to my PC instead of typing.

Last step of the Walking Skeleton (see `SKELETON.md`): the HUD window shows what the hub knows. After this plan, `uv run snow run` opens a dashboard that live-updates when `uv run snow dev say "..."` is used.

<objective>
Build the Electron dashboard window on the plan 01-07 toolchain, connect it to the hub over the loopback WebSocket with the token handoff, and render the state word and the conversation from snapshot plus deltas, verified end to end against a scripted mock hub.

Purpose: HUD-03 requires the HUD to react to local events only; VOIC-08 requires the user to see what Snow heard. Both need a HUD that is a pure WebSocket client of the hub.
Output: Electron main, preload and renderer, mock hub, Playwright smoke test.
</objective>

Handle `snapshot` (replace everything), `presence.state`, `mute.changed`, `conversation.started` (clear rows), `conversation.ended` (clear rows; plan 01-21 adds the 2 s hold and fade), `transcript.partial`, `transcript.final`, `reply.delta`, `reply.final`, `reply.interrupted`, health, `voice.status`, `stt.status`. Ignore unknown types (forward compatible). Keep audio levels out of React state (plan 01-19 reads them from a ref). `App.tsx`: the state word (Display 28px/600) mapped from presence: sleeping -> "Standing by", listening -> "Listening", thinking -> "Thinking", speaking -> "Speaking", muted -> "Muted", connection offline -> "Reconnecting"; below it a plain list of rows labelled "You" and "Snow" (plan 01-21 replaces it with the full TranscriptView). Text renders as React text nodes only.
