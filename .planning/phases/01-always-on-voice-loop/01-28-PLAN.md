    - pocket raising EngineError while synthesizing chunk 2 of 3 -> chunks 2 and 3 are spoken by kokoro, in order, with no gap longer than the kokoro synthesis time and no repeated audio for chunk 1
    - an engine disabled in tts.toml is never selected; an engine named in the order but not registered is skipped
    - when every engine fails, the router publishes health.subsystem(speech_output, down) and the HUD still shows the reply text (no crash)

  <action>
1. `tts/kokoro.py`: `KokoroEngine(cfg)` with kokoro-onnx 0.6.1 int8 model and `voices-v1.0.bin` from the kokoro-onnx GitHub release `model-files-v1.0`, downloaded on first use into the gitignored `models/kokoro/` and checked against SHA-256 values pinned in tts.toml; `voice = "bm_george"` (British male, measured present), `speed = 1.0`, onnxruntime `intra_op_num_threads = 4`; synthesis per chunk in a thread (it is not streaming; first-clause chunking keeps the first wait short, research F2).

2. `tts/router.py`: `VoiceRouter(engines: dict[EngineName, TtsEngine], cfg, publish)`. `select(emotion, big_moment) -> TtsEngine` walks `[router] order` and returns the first enabled, registered and available engine; per D-33 `cartesia` is eligible only for `big_moment` replies and `chatterbox` only when its own policy says so (both registered by plans 01-31 and 01-33; absent here). `async speak(chunks, emotion, big_moment)` streams chunk by chunk to `Playout`; on `EngineError` or `EngineLoadError` mid-reply it marks that engine unavailable (with the error kind), publishes `voice.switch` and `voice.status`, and re-speaks the failed chunk and the rest on the next engine (SPCH-03: never silent). `cancel()` stops the active engine. `voice_role` mapping: pocket_tts everyday, cartesia big_moment, chatterbox gpu, kokoro fallback. Load all enabled engines at startup in the background; Pocket failing to load selects kokoro from the first reply. The in-character one-time remark (D-17) is produced by the brain from the `voice.switch` event (plan 01-16).

3. Pipeline uses `router.speak` instead of the plan 01-26 direct engine call; `[engines.kokoro] enabled = true`, `voice = "bm_george"`, model URLs and `sha256` values in tts.toml.
