  <action>
1. Isolated environment (chatterbox-tts 0.1.7 pins numpy below 2, torch 2.6.0, transformers 5.2.0 and gradio 6.8.0, which conflict with pocket-tts's numpy 2 requirement, so it cannot share the core environment): `engines/chatterbox/` is its own uv project (`.python-version` 3.12, `requires-python = "==3.12.*"`, dependency `chatterbox-tts==0.1.7`, `torch==2.6.0` and `torchaudio==2.6.0` from an explicit `[[tool.uv.index]]` named `pytorch-cu124` at `https://download.pytorch.org/whl/cu124` via `[tool.uv.sources]`, same `exclude-newer` as the root). Run `uv lock` and `uv sync` inside it (about 2.5 GB of CUDA wheels; disk is fine, D-41).

2. `engines/chatterbox/server.py`: reads JSON lines on stdin: `{"op":"load","device":"cuda","reference":path|null}` loads the base `ChatterboxTTS.from_pretrained(device="cuda")` (base model for the `exaggeration` dial, D-33) and prepares the reference clip; `{"op":"speak","id":..., "text":..., "exaggeration":x, "cfg_weight":0.5}` generates and writes `uint32 length + float32 PCM` frames to stdout, then a zero-length frame; `{"op":"vram"}` answers with `torch.cuda.max_memory_allocated()`; `{"op":"quit"}`. Diagnostics only on stderr.

3. `tts/chatterbox.py`: `GpuPolicy(cfg)` (`psutil.sensors_battery()`; `nvidia-smi --query-gpu=memory.free,utilization.gpu --format=csv,noheader,nounits`; thresholds `min_free_vram_mb` (start 3500, then set from the measured VRAM plus 512 MB) and `max_gpu_util = 30`; re-checked every 30 s). `ChatterboxEngine(cfg, policy)` starts the server lazily with `engines/chatterbox/.venv/Scripts/python.exe engines/chatterbox/server.py` only when the policy allows, stops it (freeing VRAM) when the policy turns false or after `unload_after_s = 300` idle, maps the reply emotion to `exaggeration` from config (`excited 0.8, content 0.55, calm 0.35, neutral 0.5, sympathetic 0.45, curious 0.6`), and uses the same consent-tagged reference clip as Pocket TTS (plan 01-32) so both local voices sound alike (D-05); with no reference configured it uses Chatterbox's default voice and the SUMMARY notes the voice shift the user accepted in D-32. Register it in the router (order from plan 01-26 already puts it before pocket_tts) with `enabled = true` in tts.toml; the pipeline publishes the policy-driven `voice.switch` and `voice.status`. The GPU is used only here (D-39).

4. Tests: `test_chatterbox_policy.py` per the behavior block (fake battery, fake nvidia-smi output, stub server script). `tests/hardware/test_chatterbox.py` marked `hardware` and `gpu`: on mains power with the HUD running, load the real model, report peak VRAM and time to first audio for one sentence, and confirm that speech recognition latency (from a parallel `turn.timing`) does not regress; write the numbers into the SUMMARY and set `min_free_vram_mb` from them.
