# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: the Phase 1 HUD only. Two windows in one Electron shell: the **dashboard** (full window) and the **mini indicator** (always-on-top, click-through). Presence element is the voice-reactive ASCII network orb, rendered in 2D for Phase 1 [D-12, D-31]. The 3D shader orb, spawn-on-demand panels, activity stream, approvals, history and phone view are later phases (see CONTEXT.md Deferred). Source tags: [D-nn] = locked decision in 01-CONTEXT.md; [default] = researcher default, open to override.

## Design System

| Property | Value |
|----------|-------|
| Tool | none [default] |
| Preset | not applicable |
| Component library | none (native HTML elements and Electron native menus; see rationale) |
| Icon library | lucide-react 1.57.0 (npm registry, checked 2026-10-14). Sizes 16 and 20 only, stroke 1.75 |
| Font | Inter Variable (`@fontsource-variable/inter` 5.3.0) for UI text; JetBrains Mono 400 (`@fontsource/jetbrains-mono` 5.3.0) for model IDs, credit numbers and timestamps. Both bundled locally, never loaded from a CDN (offline-safe, nothing leaves the PC) |

**Rationale for `Tool: none` [default]:** the shadcn gate could not be asked interactively in this run. Defaulted to N because the Phase 1 HUD has about six custom components, uses no overlays beyond one native context menu, and Phase 6 replaces the visual layer with a bespoke ASCII design system, so a Radix/shadcn dependency tree would be carried for little. Override by running `npx shadcn init` before planning; the tokens below map 1:1 onto shadcn CSS variables.

**Styling approach:** Tailwind CSS 4 with every token below declared once as a CSS variable in `@theme` / `:root` (`--snow-*`). Components reference variables only, never raw hex. This is what lets Phase 6 restyle rather than rebuild. Dark theme only in Phase 1; there is no light theme and no theme switch.

**Component boundaries (build these, nothing else):**

| Component | Used in | Notes |
|-----------|---------|-------|
| `Presence` | dashboard, mini | Orb. Props `{ state, size }`; reads mic and TTS levels from refs, not React state. Phase 6 swaps the internals, keeps the props |
| `TranscriptView` | dashboard | Chat-style list, live partial row, system rows |
| `HealthPanel` | dashboard | Subsystem rows and Language models rows |
| `VoiceCard` | dashboard | Last voice engine, Cartesia credits, speech-to-text source |
| `MuteButton` | dashboard | The only primary button in the phase |
| `MiniIndicator` | mini window | Orb, caption pill, badge |
| `StatusChip` | health rows, mode | Icon plus text label, never color alone |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, chip inner gap |
| sm | 8px | Row gaps, chip padding, caption pill vertical padding |
| md | 16px | Card padding, gap between cards, window edge padding |
| lg | 24px | Gap between groups inside a card |
| xl | 32px | Orb block vertical rhythm |
| 2xl | 48px | Empty-state vertical offset |
| 3xl | 64px | Not used in Phase 1 (reserved) |

Exceptions (fixed dimensions, all still multiples of 4):
- Orb diameter: 192px in the dashboard, 40px in the mini indicator.
- Mute button height 40px; chip height 24px; health row height 32px.
- Window sizes: dashboard default 960x640, minimum 800x560; mini window 320x56.
- 1px borders and the 2px focus ring are not spacing and are exempt.

Radius: 12px cards, 8px buttons and inputs, 9999px chips and caption pill. Elevation: none. No shadows on cards (flat, 1px border). The only glow in the product is on the orb.

## Typography

Exactly four sizes and two weights. Weights: 400 (regular) and 600 (semibold).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (600 for card titles and speaker names) | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Usage map:
- Display: the state word under the dashboard orb ("Listening").
- Heading: empty-state headings and the connection banner title.
- Body: transcript text, health row names, mini caption, button text.
- Label: chips, timestamps, section headers inside cards, helper text. Mono (JetBrains Mono 400 at 12px) for model IDs and credit numbers.

Rules: no letter-spacing changes, no uppercase transforms, no italics. Numbers in credits use `font-variant-numeric: tabular-nums` and thousands separators.

Orb state hues (the orb is the only place these appear at large scale):

| State | Hue | Motion signature (so state is readable without color) |
|-------|-----|------------------------------------------------------|
| sleeping (standing by, includes soft sleep) | `#64748B` slate, 45% opacity | Slow 6 s breathing, ignores audio |
| listening | `#67E8F9` cyan | Core scales with mic level; thin outer ring expands with level |
| thinking | `#A78BFA` violet | Slow 2.4 s pulse plus rotating gradient, ignores audio |
| speaking | `#F0ABFC` pink | Core scales with TTS level; solid soft glow, no ring |

Accent reserved for (never "all interactive elements"):
1. The orb in the `listening` state.
2. The 2px keyboard focus ring on every focusable element.
3. The "Mute microphone" button text and 1px border. The "Unmute microphone" button (shown only while muted) uses the alert hue `#F87171` for text and border instead.

5. The active-provider dot in a language-model role row.

Status never relies on color alone: every status has an icon (lucide `Check`, `Loader`, `RotateCw`, `AlertTriangle`, `XCircle`, `CircleDashed`, `MicOff`, `Moon`) and a text label.

## Layout and Window Contract

### Dashboard window [D-11, D-14, D-15]

Native Windows frame, `backgroundColor: '#0B0E14'` (no white flash), `nativeTheme.themeSource = 'dark'`. Two columns with 16px outer padding and 16px gaps.

```
+--------------------+-----------------------------------------+
| Presence card      | Transcript card              (flex 1)   |
|  orb 192px         |  chat list, newest at bottom            |
|  state word        |                                         |
|  mode chip         |                                         |
|  [Mute microphone] |                                         |
+--------------------+-----------------------------------------+
| Voice card         | Health card (auto height, two columns)  |
|  active voice      |  Subsystems        | Language models    |
|  credits           |                    |                    |
+--------------------+-----------------------------------------+
   left rail 320px            right column = remaining width
```

- Left rail: Presence card on top, Voice card below. Right column: Transcript card fills remaining height (min 240px), Health card sits at the bottom at natural height.
- Below 880px window width the Health card stacks to one column (Subsystems above Language models). Minimum window 800x560.
- Primary visual anchor: the Presence orb and its state word. The eye lands there first; the transcript is secondary, and the Voice and Health cards are tertiary.
- A full-width banner row appears above both columns for the two global conditions only: hard mute (red) and core connection lost (red). It pushes content down; it never overlays.

### Mini indicator window [D-11, D-13]

Frameless, transparent, `alwaysOnTop: true` (level `floating`, not `screen-saver`, so it does not sit over fullscreen games), `skipTaskbar: true`, `focusable: false`, `resizable: false`, 320x56.

- Default position: top-right of the primary display work area, 16px from the top and right edges. Position (DIP coordinates plus display ID) is persisted and restored; on restore it is clamped into the nearest display work area, and if the saved display is gone it resets to the default.
- Content row: `[caption pill][orb 40px]`. The orb sits at the screen-side edge; the caption grows toward the screen interior. If the window center is on the left half of its display, the row mirrors (`[orb][caption]`).
- **Click-through with an interactive orb:** the window calls `setIgnoreMouseEvents(true, { forward: true })` always; the renderer sends IPC to switch it to `false` on `pointerenter` of the orb and back to `true` on `pointerleave`. The caption pill and all empty window area stay click-through at all times.
- **Click versus drag:** do NOT use `-webkit-app-region: drag` (it swallows clicks). Orb `pointerdown` starts tracking; movement under 4px then `pointerup` = click (open dashboard); movement of 4px or more = drag, window follows the pointer via IPC, position persisted on `pointerup`. Dragging never opens the dashboard.
- Orb `contextmenu` shows a native Electron menu: "Open Snow", "Mute microphone" or "Unmute microphone", "Quit Snow".
- Idle (not in conversation): orb only. In conversation: caption pill of what Snow heard (see Interaction Contract). Hard-muted: orb in muted state plus a persistent "Muted" pill that does not fade. Any subsystem Down or Restarting: an 8px alert dot on the orb's top edge, persistent until healthy.
- Autostart behavior: when launched with `--autostart` (Windows logon), the shell starts with only the mini indicator; the dashboard stays hidden until clicked or opened from the tray. A manual launch opens the dashboard. A second launch focuses the dashboard (single instance).

### Window transitions and render budget [D-11]

- Dashboard minimize button and the close (X) button both do the same thing: hide the dashboard and show the mini indicator. Snow keeps running. Quit exists only in the tray menu and the mini context menu.
- Clicking the mini orb, the tray icon (left click) or "Open Snow" restores and focuses the dashboard and hides the mini indicator. Never show both windows at once.
- While the dashboard is hidden it renders nothing: cancel the orb `requestAnimationFrame` loop, unmount the transcript and health trees, and keep no per-frame work. On show it requests a fresh snapshot (state, transcript of the current conversation, health, voice, providers) and rebuilds, so a conversation in progress is fully visible after restore.
- Frame rates: dashboard orb 60 fps; mini orb 30 fps; both 0 fps when hidden; sleeping state 15 fps. Orb is a Canvas 2D glyph renderer (pre-rendered glyph atlas, `drawImage` per glyph, no per-frame text layout); no WebGL in Phase 1, so the GPU stays free for speech-to-text.

### Tray [D-10, D-11]

Icon is a tiny rendering of the ASCII orb (16/32px, a few bright nodes and lines in the current state hue; muted adds a slash) [D-31]. The same tiny orb is the app icon and Snow's avatar beside "Snow" in the transcript. No snowflake or other logo. Tooltip: "Snow: {state word}". Left click: open or focus the dashboard. Right click menu, in order: "Open Snow", "Mute microphone" / "Unmute microphone", separator, "Quit Snow". Quit has no confirm dialog (recoverable by relaunch or next logon, and no work is lost in Phase 1).

## Orb (Presence) Contract [D-12]

**Look [D-12, D-31]:** a sphere of nodes connected by thin lines, built entirely from ASCII characters, digits and short code fragments (for example `for`, `{}`, `=>`, `0x`), each glyph keeping its own color, in the current state hue blending toward violet. Brighter glyphs at the nodes, dimmer along the lines. Glow on the orb only. Visual target: `refs/snow-vision-ascii-orb-dashboard.png` (the orb only). Level of detail: the 192px dashboard orb shows a dense glyph sphere; the 40px mini orb and the icons show fewer, larger, brighter glyphs and nodes so they stay readable. Motion: slow rotation of the sphere, glyphs flickering to new characters at a low rate, and outward ripples or swelling driven by the audio level. Phase 6 replaces this renderer with the 3D shader version behind the same props.

States are driven by core events, never by the network or the LLM, so the HUD reacts inside 100 ms (HUD-03).

| Core signal | Orb state | State word (Display) | Mode chip |
|-------------|-----------|----------------------|-----------|
| idle, waiting for wake phrase | sleeping | Standing by | none |
| soft sleep ("Snow, go to sleep") | sleeping | Standing by | "Asleep" with `Moon` icon |
| wake detected, or in conversation awaiting user | listening | Listening | none |
| user turn ended, waiting for first reply audio | thinking | Thinking | none |
| TTS audio playing | speaking | Speaking | none |
| hard mute | muted | Muted | none (banner carries the message) |
| HUD lost the core socket | offline | Reconnecting | none |

Behavior rules:
- State change: the new hue and motion signature are painted on the first frame after the event arrives; a 120 ms cross-fade settles the transition. Budget: event received to first painted change at most 50 ms, measured with `performance.mark` in a Playwright test against a mock core.
- Level mapping: orb scale = `1 + 0.18 * level`, level 0..1, smoothed with attack 40 ms and release 200 ms. Listening uses mic level; speaking uses TTS level. Level samples arrive at about 30 Hz as `audio.level { source: "mic" | "tts", level }`. Mic level is only sent while listening; TTS level only while speaking; none while sleeping, thinking or muted (so a sleeping orb never mirrors ambient room noise).
- Barge-in: speaking to listening is immediate (no cross-fade wait); the scale smoother resets so the orb does not "ring out".
- Reduced motion (`prefers-reduced-motion: reduce`): breathing and pulse animations off, sphere rotation and glyph flicker off, scale reaction capped at +6%, hue changes remain.
- The orb has a text equivalent: the state word and `aria-label="Snow, {state word}"`. The dashboard orb is a `<button>` that toggles hard mute (same action as the Mute button, [D-10]); the mini orb is a button that opens the dashboard.

## Interaction Contract

### Mute and sleep [D-10, VOIC-03]
- **Hard mute** is unmistakable in three places at once: (1) dashboard banner, full width, red tint `rgba(248,113,113,0.12)` background, 1px `#F87171` border, `MicOff` icon, text "Microphone is muted. Snow cannot hear you."; (2) orb in muted state; (3) mini "Muted" pill and tray slash icon.
- Unmute is click only: the dashboard Mute button (label flips to "Unmute microphone"), the dashboard orb, the tray menu item, or the mini context menu. No voice path and no confirm dialog. Mute also takes effect by voice ("Snow, mute") with no UI action; the HUD simply reflects the `mute` state event.
- **Soft sleep** shows the "Asleep" chip; there is no button for it (voice only, "Snow, go to sleep"). Saying "Hey Snow" wakes it.
- The Mute button reflects confirmed core state, not optimistic state: on click it shows a 120 ms pressed state and the label flips only when the core's `mute.changed` event arrives. If the core is unreachable the button is disabled and the banner says so.

### Transcript [D-14, VOIC-08]
- Rows: user messages right-aligned in a bubble filled `#0B0E14` with a 1px `#222A3A` border (the transcript card itself is `#131824`), max width 80%. Snow messages left-aligned, no bubble, speaker label "Snow" (Label 12/600, `--snow-text-3`). User label "You". Timestamps (Label, mono, `--snow-text-3`) appear on hover/focus only.
- Live user words: the partial row renders in `--snow-text-2` with an accent caret; each STT partial replaces the whole partial string (words may revise). On the final transcript the row turns `--snow-text` and the caret disappears. A turn that ends with no recognized speech removes the partial row.
- Snow replies append sentence by sentence as the LLM streams, in `--snow-text`. A reply cut off by barge-in keeps the text received so far, dims to `--snow-text-2`, and gets an "Interrupted" chip.
- System rows (provider switch, voice switch, errors): centered, Label size, `--snow-text-2`, leading status icon. Plain wording, no persona.
- Scrolling: newest at the bottom, auto-follow while the user is within 24px of the bottom. If the user scrolls up, auto-follow pauses and a "Jump to latest" pill (Label, 8px radius pill, bottom-center of the card) appears; clicking it scrolls to the bottom and resumes follow.
- End of conversation [D-14]: on `conversation.ended` the transcript stays readable for 2 s, fades out over 300 ms, then shows the empty state. If a new conversation starts within that window it clears immediately. Full history lives in the event log, not here.

### Mini caption [D-13]
- Shows the user's words (live partial, then final), not Snow's replies. Appears with a 120 ms fade-in on the first partial of a turn, updates in place, holds 2.5 s after the final transcript, then fades out over 400 ms. Never shown while sleeping.
- Single line, never wraps, never resizes the window. Overflow shows the tail of the text (newest words) with a 24px mask fade on the left edge. Max pill width 256px, height 32px, padding 8px 16px, text Body.

### Health [QUAL-03, D-15, D-25, D-28]
- Subsystem rows render from the health snapshot (do not hard-code the list). Each row: name (Body), status chip. Statuses: Running (`Check`, `--snow-ok`), Starting (`Loader`, text-2), Restarting (`RotateCw`, warn), Down (`XCircle`, alert). Expected Phase 1 set: Wake word, Speech to text, Speech output, Brain, Event log, plus anything else the supervisor reports.
- Language models: three role rows (Brain, Fast, Vision). Row = role name, then active `provider / model` in mono with an accent dot, then a chip. Chip values: Active, Fallback in use (warn, shows "{n} of {m}"), Cooling down until HH:MM (warn), Failing (alert), Not configured (text-3, `CircleDashed`), Not used yet (Vision only in Phase 1, text-3). A role row is a disclosure (`aria-expanded`); expanding lists the ordered chain, one line per entry with provider, model, and that entry's own status chip, so "Not configured" providers are always inspectable. Collapsed by default. A one-line summary under the header always shows the count: "{n} of 5 providers not configured" (hidden at zero).
- Changes in a status update in place with a 120 ms cross-fade; no row reordering, no layout shift.

### Voice card [D-15, D-17, D-33, D-37, D-38] (revised 2026-10-15)
- Row 1: "Voice" and the engine that spoke the last reply: "Pocket TTS" (everyday), "Cartesia" (big moments), "Chatterbox" (GPU, when allowed) or "Kokoro" (last fallback), with the configured voice name. A chip says "Everyday", "Big moment", "GPU" or "Fallback" (warn, Kokoro only).
- Row 2: "Cartesia credits" with remaining credits in mono (tabular, thousands separators). Under 10% remaining: number turns `--snow-warn`. At zero or when Cartesia is unreachable: a Label line explains that big moments use the everyday voice (copy below). Recovery is automatic.
- Row 3: "Speech-to-text" and the source of the last final transcript: "Groq cloud" or "Local (Moonshine)". A chip says "Primary" or "Fallback" (warn). On fallback, a Label line explains why (copy below).

### Keyboard and accessibility
- Every control is a real `<button>` or disclosure, reachable by Tab in reading order: Mute button, dashboard orb, role disclosures, "Jump to latest". Focus ring 2px `#67E8F9`, 2px offset, never removed.
- The transcript container is `role="log"` with `aria-live="polite"`; only finalized lines and system rows are announced (partials are not). A visually hidden `role="status"` region announces only: muted, unmuted, subsystem Down, connection lost, connection restored.
- All text meets 4.5:1; UI component edges meet 3:1. Targets are at least 32px high (mute button 40px). The mini window is `focusable: false` by design (it must never steal focus); its function is duplicated by the tray menu, which is keyboard reachable.
- There is no push-to-talk key and no global hotkey in Phase 1 [D-07].

### Motion tokens
Durations: 120 ms (fast: fades, press, status change), 200 ms (base: panel content), 400 ms (slow: caption fade-out). Easing `cubic-bezier(0.2, 0, 0, 1)` for entrances, `linear` for continuous orb motion. Nothing animates layout (no height or position transitions on lists).

## HUD Data Needs (for the planner; event contract is Pydantic-first, TS types generated)

Minimum signals the core must provide to the HUD over the loopback WebSocket, as a snapshot on connect plus deltas:

| Signal | Used by |
|--------|---------|
| `presence.state` (sleeping / listening / thinking / speaking / muted) plus `mode` (awake / soft_sleep) | Orb, state word, tray, mini |
| `audio.level { source: mic|tts, level }` about 30 Hz, only in the matching state | Orb |
| `transcript.partial`, `transcript.final` (user); `reply.delta`, `reply.final`, `reply.interrupted` (Snow); `conversation.started`, `conversation.ended` | Transcript, mini caption |
| `mute.changed { muted }` | Banner, button, tray, mini |
| `health.snapshot` / `health.changed` (per subsystem status; per provider status incl. not_configured, cooling_down_until; per role active provider/model, chain entry statuses, fallback index) | Health panel |
| `voice.status { engine: pocket_tts|cartesia|chatterbox|kokoro, voice_name, credits_remaining|null, cartesia_available, reason }` | Voice card, system rows |
| `stt.status { source: groq|local, reason, retry_after|null }` | Voice card, system rows |
| Provider-switch and voice-switch notices as system events | Transcript system rows |

The HUD is a WebSocket client only; it never needs Electron IPC for data (IPC is limited to window chrome: show/hide, drag, click-through toggle, tray, menus).
